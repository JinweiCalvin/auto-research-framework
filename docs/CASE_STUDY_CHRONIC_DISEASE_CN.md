# 慢病管理案例：流程如何从真实项目中调整

这是一份方法层面的匿名案例，说明通用工作流吸收了哪些使用经验。它不包含队列原始数据、未发表研究结果、专家姓名、API 请求内容或论文稿件。

## 案例暴露的问题

该课题从候选研究故事不断扩展到公开队列分析、问卷映射、图谱/LLM 比较、模拟、缺失处理、论文图表和多轮修稿。多轮迭代中出现三个典型风险：

1. 候选故事、研究假设和已验证结论容易混在一起。
2. 在 CHARLS 与 HRS 之间对齐 ADL 项目时，语义、回答选项、代理回答和跳题规则需要逐条核对；仅靠相似措辞或模型判断不够。
3. 实验矩阵与论文篇幅不断扩张，但校准、端点数值可靠性、样本选择和真实队列可比性等核心审稿问题需要明确关口逐项处理。

## 转成通用流程的改进

| 案例中的工作 | 固化为通用流程 |
|---|---|
| Idea2Paper 多轮生成、导师修订 | 每次输出用 run ID 冻结；研究者先选定科学问题，评分只作筛选信号 |
| 专家审阅 ADL 候选对应 | 原始出处、候选状态、不确定选项先整理好；专家只处理需要专业判断的最小表单；分歧记录裁决 |
| 图谱、文本匹配、LLM 对照 | 方法比较作为独立、可复现的实验；不让模型替专家冻结主要 crosswalk |
| CHARLS→HRS 测量链接 | 将映射和 DIF 限制作为显式敏感性设定；无共同受访者或外部锚点时，不把结果讲成已验证链接 |
| 覆盖率、优化端点审稿意见 | 在实验计划阶段预列覆盖/可行性/弃答/端点误差诊断；数值稳定性与全局最优性分别报告 |
| 重复划分、死亡和缺失结局分析 | 预先定义信息条件、结局状态、选择分析、校准和不确定区间；真实数据分析有单独审计表 |
| 多版本图、表和论文稿 | 图表从脚本生成、文件名带版本，论文 claim 与结果路径相连；先做 claim audit 再排版 |
| GPU 夜间运行 | 只在计划和预算关口通过后启动；记录设备/时限/停止条件，结果传回后关机 |

## 适用范围

这些改进适用于有多源数据、测量/标注映射、外部验证或较长实验链条的课题。轻量研究不必执行每个环节：例如没有模型训练就跳过 GPU；不涉及专业映射就不设专家表；没有足够目标域样本就不要做昂贵的跨域分析。每一步是否启用由研究问题决定。
